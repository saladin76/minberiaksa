## السبب والإصلاح

Next يعالج علامة `server-only` داخل عملية بنائه؛ نجاح البناء لا يثبت إمكان استيراد الوحدات نفسها من Node/tsx مستقل. لم تكن الحزمة معلنة في تبعيات التشغيل. أُضيف `server-only@0.0.1` بتثبيت صريح في package.json وpackage-lock، دون إزالة حماية العميل.

كشف اختبار الاستيراد الحقيقي أيضًا أن tsx قد يعرض صادرات TypeScript المترجمة إلى CommonJS داخل `default`. أضيف محمّل موحّد يتعامل مع الصادرات المسماة وdefault، واستُخدم في أوامر التهيئة الأربعة.

المُشغّل يختار Node المطابق لمحرك المشروع من NVM إذا كانت جلسة SSH على إصدار مختلف. قبل أي خطوة تهيئة يشغّل استيرادًا فعليًا للوحدات والدوال المطلوبة، بعنوان قاعدة بيانات وهمي وfetch محظور. أي نقص يوقف جميع الخطوات قبل إنشاء مسودات أو طلبات نشر جزئية. أصبح هذا الفحص جزءًا من مساري البناء أيضًا.

المراجع: [توثيق Next الرسمي لحماية وحدات الخادم](https://nextjs.org/docs/app/getting-started/server-and-client-components#preventing-environment-poisoning).

## التحقق

- خمس حالات رجوع تختبر الحزمة في قفل تبعيات الإنتاج، وبقاء رفض استيرادها من العميل، واستيراد وحدات التهيئة الحقيقية وصادراتها، والتوقف قبل أي خطوة عند فقد الحزمة، ومتابعة الخطوات المستقلة وتقرير إخفاقها، واختيار Node الصحيح من جلسة تحاكي Node 22.
- أُجري npm ci نظيف للحزمة من بيانات القفل الفعلية مع omit=dev ومن الذاكرة المحلية للحزم؛ نجح استيراد empty.js تحت شرط react-server من مجلد الاختبار نفسه.
- الفحص الحقيقي أعاد runtimeImportsReady=true تحت Node 24.22.1، دون اتصالات مزود أو كتابة في قاعدة الإنتاج.
- أُصلح مسار Node في fixture اختبار Cron حتى لا يصبح symlink دائريًا عندما يعرض المنفذ process.execPath على هيئة node فقط؛ لم يتغير منطق Cron في الإنتاج.
- نجحت اختبارات المحتوى 199/199، والتكامل 1324/1324، وفحوص الأنواع وlint دون أخطاء أو نتائج جديدة. نجح بناء Next.js 16.4.3، وفحص TypeScript الخاص به، وتوليد 152/152 صفحة ثابتة.
- بيئة الاختبار الحالية لا تتيح ملفات /proc الخاصة بقياس RSS؛ استُخدم مكيّف محلي لقياسات الذاكرة يعتمد V8/getrusage عند فشل القراءة. هذا ملف اختبارات مؤقت غير مرفوع وغير مستخدم في الإنتاج. كما بقيت أقفال Cron الخاصة بالاختبارات داخل مجلداتها المعزولة، دون تغيير سكربت Cron المنشور.

## النشر وإعادة المحاولة

استخدم أمر النشر المحمي مع SHA الإصلاح الكامل، ثم:

```bash
node scripts/finalize-reviewed-dashboard.mjs --apply --publish --activate-approved
```

لن تحتاج إلى اختيار Node يدويًا إذا كان Node 24 المثبت متاحًا في NVM. الفحص المبكر يفشل بوضوح إن تعذر العثور عليه أو استيراد الاعتمادات. اعتماد Meta يظل إجراءً منفصلًا عند المزود، وقد تبقى لغات قيد المراجعة؛ لا تُعتبر القوالب معتمدة لمجرد نجاح التشغيل.
