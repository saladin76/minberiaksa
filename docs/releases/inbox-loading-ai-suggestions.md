# Inbox metadata and long editor suggestions

Business-number options load from an authenticated metadata endpoint independently of the archive. Failed refreshes retain confirmed numbers and display an error. Pending or failed counts never render an empty-success badge. List polling skips overlapping work and cancels stale client requests.

The topbar reads a count-only endpoint without donor/sender hydration. Concurrent readers share only pending archive aggregates; completed snapshots and read markers are not cached. Additive compound indexes support archive grouping and marker lookups. All conversation identities remain scoped to the business sender and contact.

Content and page SEO suggestions request an asynchronous result with `Prefer: respond-async`. The existing authenticated, revision-checked handler runs through Next.js `after()` with a detached, bounded signal. Polling reads the retained result without repeating generation. Tasks belong to the initiating operator, enforce current section permission and any analytics source permission on reads/cancellation, expire after 24 hours and never publish content. Idempotent request identifiers prevent a replay from scheduling another worker. Cancelled tasks cannot overwrite their retained state; running workers also check durable cancellation. A killed worker reaches a controlled deadline and is never automatically retried.

Provider errors retain only allowlisted stage and parameter categories. Shared failures show their actionable reason at the top of the editor and stop remaining locales. Research requests use the minimal hosted-search tool contract; researched translation disables provider storage. The opt-in synthetic diagnostic shares the live request builders, prints no secrets or generated content, and performs no provider calls without `--check-generation`. Metadata access alone does not certify generation or billing readiness.

Validation: 1,122 integration tests, 160 content tests, complete TypeScript, the existing lint ratchet, dashboard translations and browser coverage for delayed inbox loading and asynchronous SEO results. The release gates also verify the production build and broader browser regressions. Provider compatibility still needs an explicit runtime generation check after deployment.
